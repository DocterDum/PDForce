## Single purpose

PDForce overrides how PDF files are handled: it makes PDFs open in Chrome's built-in viewer, or download instead, according to a single user-chosen setting.

## Detailed description

Some sites force PDFs to download when you only wanted to read them. Others open a PDF in the viewer when you were trying to save it. PDForce puts that choice back in your hands.

Pick one of three modes from the toolbar:

• Off — no interference, sites behave as they normally would.
• Force View — PDFs open in Chrome's built-in PDF viewer.
• Force Download — PDFs are saved to your computer.

PDForce works in two ways. It adjusts the Content-Disposition and Content-Type response headers of PDF page loads, which covers ordinary links, redirects, form submissions and URLs with no .pdf extension. It also adjusts the "download" attribute on PDF links in the page, so links a site marked as downloads can be opened in the viewer, and vice versa.

Your choice is remembered until you change it. The extension sends no data anywhere, contains no tracking or analytics, and does not read page content — it only looks at link addresses to decide which links are PDFs.

Some downloads are built entirely in JavaScript by the page (for example blob: saves) and cannot be redirected by any extension. Those are out of scope and will keep behaving as the site intends.

PDForce is free and open source, licensed under the AGPLv3. Source: https://github.com/DocterDum/PDForce

## Permission justifications

**declarativeNetRequest** — Used to declare static rules that rewrite the Content-Disposition and Content-Type response headers of PDF page loads, so the PDF opens in the viewer or downloads according to the user's chosen mode. Rules apply only to main-frame document requests. The extension does not read, block, or redirect requests, and does not receive request data.

**declarativeNetRequestWithHostAccess** — Response-header modification requires host access. This permission lets the header rules apply on sites the user has granted access to, without giving the extension the ability to observe request contents.

**Host permissions** — PDFs can be served from any website, so the user's chosen mode has to apply anywhere they open a PDF. Access is used solely to apply the header rules and to adjust the download attribute on PDF links. No page content is read, collected or transmitted.

**storage** — Stores a single value: the user's selected mode (off, view or download), so the choice persists across browser restarts and is shared between the popup, the background service worker and content scripts. Nothing else is stored.

**Remote code** — Not used. Answer "No, I am not using remote code": every script executes from files inside the package, with no eval, no remotely hosted script and no external module.

## Data usage

No user data is collected, used, sold or transferred. The only stored value is the selected mode, kept locally in `chrome.storage.local`.
